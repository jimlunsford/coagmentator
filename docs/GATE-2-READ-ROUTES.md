# Gate 2 Read Route Specification

Prepared: 2026-10-05. **Proposed implementation mapping, not an implemented API or a contract revision.** Read with [CONTRACTS](CONTRACTS.md), [CAPABILITIES](CAPABILITIES.md), [ERRORS](ERRORS.md), [GATE-2-IMPLEMENTATION-PLAN](GATE-2-IMPLEMENTATION-PLAN.md) and [TEST-MATRIX](TEST-MATRIX.md).

## Rules inherited by every row

Each route is independently registered as POST under `/wp-json/coagmentator/v1/`. There are exactly nine routes in this gate. There is no operation parameter, wildcard callback, GET variant or arbitrary native REST forwarding. The normal plugin binds each fixed path to its dedicated operation, although shared validation/serialization code is allowed. The guard independently pins the same route/method set and registered callback identities.

**Authentication:** every route requires the configured service user, a real current-request approved Application Password UUID authentication event, valid HTTPS/trusted-proxy configuration, the healthy MU guard, active normal handlers, current credential validity, fixed site/actor binding and BASE (`coagmentator_read` plus native `read`). No cookie/nonce-only, OAuth-token, main-password or alternative-user access. MCP's future `coagmentator.read` scope is not a token the WordPress bridge accepts.

**Envelope:** exactly `contract_version: "1.0"`, `correlation_id: UUIDv4`, `site_id: UUIDv4`, `actor_id: configured ASCII identifier`, `arguments: object`. Reject mutation bookkeeping, `policy_version`, unknown envelope/argument fields, null where not permitted, duplicate JSON members, arrays as top-level requests, coerced numbers/booleans and JSON batches. The server checks identity before detailed validation. Validate raw JSON rather than WordPress's merged/coerced request parameters.

**Transport/limits:** UTF-8 `application/json`; no query parameters, compression, redirects, JSONP, method overrides or alternate route encodings. 2,097,152-byte request/response maxima; lists additionally 1,048,576 bytes; JSON depth 20; 15-second operation budget; read admission 60/minute, four active requests, pre-auth 120/IP/minute. Lower effective configured limits apply and are advertised. Byte checks apply before buffering at ingress and after encoding at egress. A raw body is at most 1,048,576 UTF-8 bytes and an excerpt 65,536; reject NUL/invalid Unicode. Output size failure returns RESOURCE_LIMIT, never truncated source or partial-success fields.

**Success:** exact `BridgeSuccess<T>` with the configured site and validated/internal correlation, `receipt: null`, JSON content type and `Cache-Control: no-store`. Output projection is a new allowlisted object, never a pass-through core REST response. No extra headers containing totals, resources, server versions, paths or user information. Editorial source and returned links remain untrusted data. BridgeSiteInfo is an internal shape, not the later model SiteInfo projection.

**Common errors:** missing acceptable identity 401 AUTHENTICATION_REQUIRED; invalid/revoked/unapproved credential 401 AUTHENTICATION_FAILED; valid wrong principal or broad missing capability 403 AUTHORIZATION_DENIED; authenticated site mismatch 409 SITE_MISMATCH; unsupported contract 422 UNSUPPORTED_OPERATION; invalid schema/cursor 400 VALIDATION_FAILED; absent/concealed resource 404 NOT_FOUND; limits 413 RESOURCE_LIMIT; admission 429 RATE_LIMITED; unexpected WordPress error 500 WORDPRESS_INTERNAL_ERROR; bridge/config/operational storage failure 500 INTERNAL_ERROR where a normalized response can be emitted. All read errors have `write_state: not_applied`, null receipt and null approval. Missing handlers/invalid guard policy can prevent authentication entirely; no successful identity or resource lookup is implied by the resulting generic failure.

**Pagination:** `limit` integer 1..50, default 20; authenticated opaque cursor at most 2,048 characters, expires after 15 minutes. Bind site, actor, route, canonical filters (including requested parent), limit and last scanned sort key. Reauthorize every page. Query in bounded batches, scan at most 1,000 candidate objects, permission-filter before selecting returned items; a short or empty page can have `next_cursor`. No total counts or unfiltered pagination headers. Keyset order and complete versions follow CONTRACTS. No offset/page argument. If a complete eligible item/result cannot fit the contract, fail explicitly; do not silently drop it as if unauthorized.

**Search semantics:** query is a literal substring over content title/body/excerpt, attachment title, or term name for the corresponding route. Escape SQL LIKE wildcard characters and bind values through prepared WordPress query adapters. No negative terms, regular expressions or query-language operators. Database collation governs case/accent matching; query never authorizes access. Add explicit percent/underscore/quote/minus cases to search tests.

Each row maps to the same named CAPABILITIES row without adding write-family authority to reads. Search filtering is per object; single-resource access conceals resource-level denial. Type/taxonomy/binding-wide denial occurs before query and is not evidence that an object exists. Explicit private search with private reads disabled returns no private rows, not an exception exposing the number of matching private objects.

## Output details that need explicit implementation tests

### Site information

Use all and only BridgeSiteInfo fields in CONTRACTS, including internal site/bridge/contract/policy information. `available_tools` can contain at most these nine implemented reads and must omit `get_mutation` and all eleven writes. `writes_enabled` is false. `metadata_keys` contains only `editorial.note`, and `seo_mode` is disabled in Gate 2. No user input selects profile, tools or limits. The declared profile may be strict or trusted according to valid host policy; this gate cannot enable writes under either.

Preserve the contract's profile semantics: strict reports its fixed unconditional approval-operation policy list and true live-edit flag, even though writes are unavailable; trusted reports empty list/false. That policy list does not advertise implemented tools. The future MCP projection filters it to its effective available set as CONTRACTS requires. `policy_version` is a positive safe integer; identity values are read from valid host policy. Trash retention comes from core, including zero, without enabling a Trash endpoint.

`Limits` retains its complete accepted closed shape, including future write/upload/journal ceilings. Those entries describe contract ceilings, not implemented Gate 3 storage or an upload feature. Effective read bounds and deadlines must correspond to enforced values. No software fingerprint or plugin inventory can be added to the shape.

### Content and revisions

Keep stored titles/slugs as existing output strings, not as newly submitted `Title`/`Slug` inputs. For example, an existing draft can have an empty title/slug without the reader repairing it. No sanitization, markup execution or editorial normalization on reads. Validate encoding/required output representations and fail safely for corrupt data. Dates must follow the accepted UTC shape; do not invent a valid timestamp for an invalid stored value.

Content hashes include enabled metadata even in search results and key-subset metadata requests; no URL/latest-revision-ID in the hash. Revision hashes include complete stored restorable fields even in revision summaries. Changes to a body, allowed metadata, ownership or relationships must invalidate the appropriate version. Strings are byte-faithful Unicode; set-valued ID arrays are sorted. Inaccessible source is never hashed for an outward result before permission checks.

For revision availability, lack of post-type revision support makes the operations unsupported. When saving revisions is disabled by configuration but stored saved revisions still exist, read those authorized saved revisions; no promise of future retention is made. If none exist, return an empty list. A requested pruned revision is NOT_FOUND. Autosave exclusion and parent checks apply regardless of core's own revision capability shortcuts. [Revision permission reference](https://developer.wordpress.org/reference/classes/wp_rest_revisions_controller/get_items_permissions_check/) and [autosave detection](https://developer.wordpress.org/reference/functions/wp_is_post_autosave/) inform the implementation, not a broader response projection.

### Media and terms

Media data is only `id`, allowed MIME, raw title, alt text, URL, dimensions, bytes, nullable stored digest, nullable supported parent and complete version. Native [attachment metadata](https://developer.wordpress.org/reference/functions/wp_get_attachment_metadata/) contains fields that must not be serialized wholesale. No local filename/path, EXIF, subsize array, attachment description/body or author is exposed. Dimensions/bytes must be known valid values, never zero placeholders for missing metadata. A missing safe digest alone may be null; missing basic eligibility is not rescued by nulling unrelated required fields.

Bounded inspection may read the authorized attachment's managed regular file, but may not accept a path, follow a URL wrapper or escape the uploads root. Inspect formats without rendering/re-encoding. Reject GIF/SVG, animated PNG/WebP and inconsistent/truncated files as ineligible. Resource-budget failure is distinguishable from ineligibility internally and never silently converts an incomplete inspection into a supported Media result. Foreign/missing parent policy is identical between search and direct reads. Never use a URL request to learn remote file size or fill a missing digest.

Terms are only category/tag objects. Query with `hide_empty: false`; usage counts must neither gate results nor appear in output. Parent filtering is exact and bounded. Return stored name/slug/description as plain data; no archive rendering or taxonomy registration from arguments. Term versions contain only the accepted projection plus hash domain. [WP_Term_Query](https://developer.wordpress.org/reference/classes/wp_term_query/__construct/) is the query reference.

### Metadata

Exact mapping: `editorial.note` to `_coagmentator_editorial_note` (4,000 scalar values); `seo.title` to `_coagmentator_seo_title` (300); `seo.description` to `_coagmentator_seo_description` (500). The SEO names remain recognized contract keys but unavailable in Gate 2. Test explicit disabled requests and omitted keys. No third-party SEO key aliases. Values must satisfy their stored scalar/string policy, and neither serialized arrays/objects nor unexpected multi-value storage is returned as a guessed string. Check both absence and stored empty string. A registered meta write callback is not a read authorization check.

## Error translation and disclosure

Use a fixed mapping, not the incoming WP_Error code/message/data. All messages and field/reason tokens are project-owned allowlists. Fields are schema-known paths only and capped at 20; no rejected values. Generate correlation internally when input is missing/invalid; never echo an unvalidated identifier. Protected audit may record the validated identity and credential UUID per SECURITY, but error text/data must not reveal it. Missing and concealed objects share code/message/reason shape and no revealing headers; equal timing is not promised.

| Internal condition/reason token | External bridge result | Disclosure/retry rule |
| --- | --- | --- |
| `authentication_required`, `authentication_failed` | AUTHENTICATION_REQUIRED/FAILED, 401 | Do not distinguish unknown username, wrong secret or revoked secret; no field validation details |
| `identity_not_allowed`, `capability_denied`, `actor_mismatch` | AUTHORIZATION_DENIED, 403 | Safe generic message, no expected IDs/capability inventory/resource state |
| `site_mismatch` | SITE_MISMATCH, 409 | Operator configuration error after auth; no expected site identity in error details |
| `contract_unsupported`, `feature_disabled`, `media_unsupported` | UNSUPPORTED_OPERATION, 422 | Only after applicable authentication/parent authorization; no internal plugin response |
| `invalid_json`, `duplicate_member`, `invalid_type`, `unknown_field`, `invalid_cursor` | VALIDATION_FAILED, 400 | Closed schema paths/reasons only; no body excerpt, SQL-like query or decoded cursor payload |
| `not_found` | NOT_FOUND, 404 | Same token for absent, wrong-type and object-level concealed denial, including cross-parent revision |
| `request_limit`, `response_limit`, `body_limit`, `deadline_exceeded` | RESOURCE_LIMIT, 413 | No partial data; retryable false; bounded scan continuation is normal pagination, not inherently an error |
| `rate_limit`, `concurrency_limit` | RATE_LIMITED, 429 | Positive bounded retry delay mirrored to Retry-After; no queue; retryable true |
| `wordpress_failure`, `invalid_stored_state` | WORDPRESS_INTERNAL_ERROR, 500 | No raw WP_Error, exception, stack, path, email, SQL or plugin data; retryable false |
| `configuration_invalid`, `guard_unavailable`, `operational_storage_failed`, `bridge_failure` | INTERNAL_ERROR, 500, if processing reached normalized bridge failure handling | Closed safe message; guard may instead deny before successful auth; no fallback access; retryable false |

Unknown routes return 404, never invoke a generic dispatcher. A service attempt at a known non-bridge API is guard-denied with no target execution. Method/encoding mismatches are rejected before route dispatch and do not create an alternate valid route. The guard's emergency response and final REST normalization must agree on the failure envelope when it can be safely formed.

Gate 2 does not emit VERSION_CONFLICT, STATE_CONFLICT, IDEMPOTENCY_CONFLICT, approval errors, RESOURCE_BUSY for editor locks, MUTATION_IN_PROGRESS, WRITE_OUTCOME_UNKNOWN or VERIFICATION_FAILED on these reads. These belong to later mutation behavior. UPSTREAM_AUTHENTICATION_FAILED and UPSTREAM_UNAVAILABLE are future MCP/transport translations, not fake WordPress route results. Test malformed proxy/host failures as HTTP failures without claiming the bridge can normalize responses it never controls.

## Review check

Nine paths, all POST, nine CAPABILITIES mappings and nine typed projections are specified above. Every common rule is mandatory for every route. No write endpoint is planned here; `get_mutation` is deferred. Functional and hostile-input coverage owners are named in TEST-MATRIX. This specification must be accepted with the preparation plan before implementation begins.
